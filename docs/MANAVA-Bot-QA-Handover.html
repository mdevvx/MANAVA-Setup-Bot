2.  System under test

A single-process Discord bot (discord.py 2.x, fully async) backed by a Supabase Postgres database accessed directly via asyncpg. It provides:

  • Squads — eligibility-gated creation, per-squad role + four channels distributed across the SQUADS 01–07 categories, membership and leadership flows (apply / invite / approve / reject / leave / remove / promote / demote / transfer / disband), 30-day archive on disband, and /admin restore-squad recovery.
  • Unified XP economy — one Personal XP balance (Discord text activity + MANAVA events), Lifetime + Season counters, 1:1 cascade into Squad XP, level-based member caps.
  • Leaderboards — global squad (Season XP, top-32 badge) and per-squad member, rendered natively.
  • Applications — Developer and Creator/Streamer review workflows with persistent Approve / Reject / Request-More-Info controls and a persistent applicant reply flow.
  • Seasons — manual Start / End / Start-New (resets Season XP, never Lifetime).
  • MANAVA Gateway integration — identity lookup (GET /internal/identity/:discordId) and HMAC-SHA256-signed inbound event webhooks, verified against MANAVA's Gateway source.

Two operating modes

Gateway mode (when MANAVA_GATEWAY_BASE_URL + DISCORD_BACKEND_API_KEY are set) uses the real MANAVA identity service and HMAC webhook verification. Stub mode (default until MANAVA supplies credentials) uses the manual /admin set-verified and /admin link-manava-account overrides and a legacy bearer-token webhook. The automated suite covers both; the live checklist in §6 is written for stub mode with a Gateway-mode addendum.

3.  Test approach & how to run

3.1   Automated (this report, §4–§5)

pytest with pytest-asyncio. Tests are unit / integration level: service logic, permission-overwrite construction, event parsing and de-duplication, HMAC signature verification, cross-squad isolation, disband cleanup and recovery, application flows, season reset, and the protected-role guard. Repositories and Discord objects are mocked, so the suite needs no live database or gateway connection and runs in ~1 second. mypy is run as a type-safety gate.

Installpython -m pip install -r requirements-dev.txt
Run testspytest -q
Type checkmypy src

Both also run automatically as the quality stage in .gitlab-ci.yml.

3.2   Manual / live-server (§6)

Items that depend on a real Discord guild, real Discord API side effects (role/channel creation, DMs), a running database, or the real MANAVA Gateway are listed as an executable checklist in §6 with explicit steps, expected results, and a result column for the tester to complete.

6.  Manual / live-server acceptance checklist

Run once against a staging guild with the bot deployed and migrations applied. Unless noted, these use stub mode (Gateway env vars unset) so /admin set-verified acts as the linked/verified gate. You will need 2–3 Discord accounts (or alts) for the membership flows. Tick Result as Pass / Fail and add notes.

#CaseStepsExpectedResult
6.1Squad creation gate — each failure With XP < 1500 / no Member role / unverified / already in a squad / a duplicate name, run /squad create. Each failed gate is listed in one plain-language message; no squad created.
6.2Eligible creation + membership flow /admin set-verified + /admin add-xp 1500, then /squad create. Second account /squad apply → approve via the DM buttons. Then /squad invite, /squad promote (3rd → blocked), /squad demote, /squad remove, /squad transfer-leadership. Role + 4 channels created under a SQUADS category; applicant DM'd on approve; officer cap of 2 enforced; every destructive action asks to confirm; leadership always present.
6.3Cross-squad isolation Create two squads with different accounts. As an officer of squad A, try to open squad B's Officer Text channel. Not visible / no access.
6.4Disband & archive; recovery /squad disband (confirm). Then /admin restore-squad squad_name:…. Access revoked immediately, squad off /leaderboard squads, rank roles removed; channels remain (30-day window). Restore re-activates it, re-adds members, re-grants access.
6.5Discord text XP Post a ≥10-char message in a normal channel; repeat within 60s; post a <10-char message; post in an excluded channel. +15 XP once; no XP on the repeat, the short message, or the excluded channel. Squad XP rises 1:1 while you're in a squad.
6.6MANAVA event pipeline (harness) /admin link-manava-account, then /xpconfig simulate-manava-event event_type:match_completed. Repeat with a fixed event_id twice. Try tournament_placement place:1. First run: status=processed, XP granted, Personal + Squad XP rise. Second identical run: status=duplicate, xp_granted=0. Placement grants participation + reward.
6.7Seasons Earn some XP. /season start, then /season new (confirm), then /season status. Personal Season XP and Season Squad XP → 0 for all; Lifetime unchanged; an audit_logs row with action = season.start_new and the actor.
6.8Developer application, end to end /apply developer → fill the form (try a bad email → Fix & resubmit) → submit. In #applications-review: Request More Info → applicant replies via the DM button → Approve. Then /apply developer again immediately; and again after a Reject. Developer Pending assigned; embed posted; a bad email blocks with Fix & resubmit; more-info reply attaches to the same record; on approve Pending→Developer and applicant DM'd; a 2nd active application is blocked; after a Reject the 30-day cooldown message appears.
6.9Reviewer permission boundary As an account holding only Moderator (or Senior Moderator), click a review button; also check /admin visibility. Review action refused (“Only Admin / MANAVA Team…”). /admin, /xpconfig, /season are hidden in the command picker for non-Administrators.
6.10Persistence across restart Submit a squad application and an app-review item, then restart the bot, then use the previously-posted buttons. The Approve / Reject / Request-More-Info / Respond buttons still work after the restart.
6.11DM-closed handling With server DMs disabled, run /squad apply; and be the target of a squad-join or application decision. /squad apply is blocked with instructions to enable DMs; a decision maker is told the applicant couldn't be DM'd.
6.12Gateway mode (once MANAVA supplies credentials + registers the URL) Set MANAVA_GATEWAY_BASE_URL / DISCORD_BACKEND_API_KEY / WEBHOOK_SIGNING_SECRET, restart. /admin gateway refresh-identity user:@you. Have MANAVA fire a real event; then have it redelivered. /admin status shows “Gateway” mode + HMAC auth. Identity returns the expected linked/verified. The real event grants XP and writes a processed_events row; the redelivery grants nothing.

8.  Known limitations & items pending external input

8.1   Accepted / by design

ItemDetail
Discord text-XP cooldown is in-memoryThe 60-second per-user cooldown resets on restart — at most one extra grant right after a redeploy. Accepted trade-off.
Text-XP grants are best-effort during a DB outageLogged and dropped, not queued.
Application field validation is format-only, post-submitDiscord modals can't validate inline; email / URL are checked on submit, with a “Fix & resubmit” recovery. No deliverability checks — reviewer's call.
Application modal is a 3-step flowDiscord's 5-input modal limit forces select menus → modal → optional comments.
Season resets are not snapshottedThe reset is audited (actor + counts) but final standings aren't stored. Export the leaderboard before /season new if a record is wanted.
contributed_xp is lifetime-of-stint, not seasonalPer spec, a season reset does not touch it.
Archived squads keep inaccessible channels for 30 daysThen a daily job purges them. Recovery via /admin restore-squad within the window.
Single instance onlyTwo processes on the same token would double-process. No leader election.
Gateway identity cache is lazyAn event for a MANAVA user the bot has never looked up is recorded as unresolved_user and grants no XP until an identity lookup warms the cache. Client confirmed acceptable for launch.
